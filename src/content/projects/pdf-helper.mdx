## Problem
Large collections of PDFs are painful to search, and standard keyword search often misses semantic context.

## Solution: RAG Pipeline
**PDFhelper** is a Retrieval-Augmented Generation (RAG) system that uses vector embeddings so queries match on meaning rather than exact keywords.

### Tech Stack
- **Embeddings:** Hugging Face `all-MiniLM-L6-v2`.
- **Vector DB:** Qdrant (local Docker instance).
- **LLM:** LLaMA 3.2 (via Ollama) for generation.
- **Orchestration:** LangChain.

## Workflow
1. **Ingestion:** PDFs are parsed, chunked (500 chars with 50 overlap), and embedded.
2. **Storage:** Vectors stored in Qdrant collections.
3. **Retrieval:** The query is embedded, then matched by Top-K cosine similarity.
4. **Generation:** Retrieved chunks plus the query go to LLaMA 3.2.

## Impact
- Cut search time by **~60%** on technical documentation.
- Runs "Chat with your Data" locally, so nothing leaves the machine.
